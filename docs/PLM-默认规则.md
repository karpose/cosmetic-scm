# PLM 默认规则

产品合规资料、原料法规目录、稳定性试验、质量标准、新品立项、受控文件、变更控制和标签设计稿的规则是我先定的默认值，等质量部确认后再改。这份清单列出每条规则现在的取值，以及要改时看哪里。

**状态**：都还没有经过质量部确认。

## 法规目录内容不是系统提供的

**系统不内置任何法规内容。** 目录要由质量或法规人员按官方发布的版本导入，并写明来源。示例数据里的条目只是为了演示功能，来源写着“示例数据，不是法规原文”，**上线前要停用**。

上线检查页会提示目录是否为空。法规更新时要重新导入，系统不会自动获取。

## 全成分表

只是**草稿**，不能直接用于标签：

- 配方里的原料按含量从高到低，含量不超过 0.1% 的标出来，排序规则要按现行法规核对。
- 复配原料没有拆成单一成分。
- 配方里没录的成分（如水）不在里面。
- 显示的是物料名称，不是标准中文名称。

**系统不内置任何标准值。** 项目、方法和限度都由质量部按公司标准填写。

| 规则 | 现在的做法 | 要改时看 |
| --- | --- | --- |
| 按什么建 | 每个物料（原料、包材、成品）一套，每次修改是一个新版本 | `QualitySpecService.create` |
| 谁能提交 | 主数据、QA、QSO。同一物料同时只能有一个待签批的版本 | `QualitySpecController`、`create` |

| 有标准的物料 | 放行前要逐项录入结果，**最近一次有效检验合格**才能放行。物料检验放行和成品上市放行都适用 | `QualitySpecService.blocker`、`QualityService` |
| 按哪个版本检验 | 录入时的生效版本。之后标准更新了，已有的检验记录照样有效，不要求重检 | `QualitySpecService.record` |
| 判定 | 填了上下限的由系统判定，人工填的合格不算数；没填的由检验员判定 | `QualitySpecService.judge` |
| 检验日期 | 不能晚于今天，不能早于生产日期 | `QualitySpecService.record` |

| 复检 | 有不合格记录后可以复检，要写原因和依据；复检合格还要等偏差关闭 | `QualitySpecService.record` |
| 结果能改吗 | 不能改。录错了由 QSO 作废（写原因，记录保留）后重录；放行或拒收以后不能作废 | `QualitySpecService.voidInspection` |
| 拒收 | 不受检验记录限制 | `QualityService` |
| 期初导入的批次 | 不检查（期初导入直接写放行记录） | `OpeningStockService` |

| 稳定性试验 | 登记时可以从成品的生效标准带入项目，带入后要按试验方案核对限度 | `Stability.vue` |
| 检验结果导出 | 质量标准页“导出检验结果”：全部批次检验，每次检验的每个项目一行，含取样情况、供方报告编号、结果来源、作废的记录和原因、不合格的偏差号；可以按检验日期过滤（接口参数 from、to）。所有内部岗位都能导，每次写审计 | `QualitySpecService.exportRows`、报表 `inspections` |

## GMP 自查（检查要点委托生产版）

依据《化妆品生产质量管理规范检查要点及判定原则》（国家药监局 2022 年第 90 号公告）附 2“委托生产版”，24 项：关键项目 1 项（第 13 项）、其他重点项目 8 项（第 2、4、9、11、16、19、23、24 项）、一般项目 15 项。系统里的“要点”是概括，检查时以原文为准。

| 规则 | 现在的做法 | 要改时看 |
| --- | --- | --- |
| 谁能做 | QA、QSO 发起、逐项登记、转 CAPA、提交、作废；QSO 签批、退回；内部岗位都能看 | `GmpSelfCheckController` |
| 期间 | 选自查期间，最长一年，结束日期不能晚于今天；默认最近 12 个月。系统按这个期间做自动核对 | `GmpSelfCheckService.create` |
| 同时进行 | 同一时间只能有一份自查在进行（自查中、待签批），签批或作废后才能发起下一份 | `gmp_self_check.open_key` 唯一约束 |
| 检查结果 | 符合、存在瑕疵（**只限关键和重点项目**）、不符合、不适用（**只限一般项目**，比如不向受托方提供物料时的第 12 项）。存在瑕疵和不符合要写发现的问题，不适用要写原因 | `GmpSelfCheckService.recordItem` |
| 转 CAPA | 存在瑕疵和不符合的项目都要转 CAPA（来源“GMP 自查”，写措施、负责人、期限）才能提交；一项只转一次 | `GmpSelfCheckService.createCapa`、`submit` |
| 结论 | 按判定原则自动算：关键项目不符合；或关键瑕疵数 + 其他重点不符合数 ≥ 4；或重点（含关键）不符合 + 重点瑕疵 + 一般不符合 ≥ 8，为**存在严重缺陷**。有不符合或瑕疵但没到上述情形，为存在缺陷；都符合或不适用，为未发现缺陷。**原文只说“有不符合规定项目”是存在缺陷，这里把瑕疵也算进去（偏严）** | `domain/rules/GmpJudgement` |
| 提交和签批 | 24 项都检查完、问题都转了 CAPA、写了总结才能提交；结论在提交时定下。签批要 QSO 输入密码，**不能是提交人**；退回后回到自查中，可以重新检查 | `GmpSelfCheckService.submit`、`approve` |
| 作废 | 自查中、待签批的可以作废，要写原因；已登记的结果和转出的 CAPA 都保留 | `GmpSelfCheckService.cancel` |
| 自动核对 | 19 项有系统核对，只读、不替代人工判定：受托厂许可证和备案（2）、质量安全负责人账号（4）、受托厂审核（6）和名录（7）、委托完工和出厂放行审核（9）、停用受托厂的在途委托单（10）、在用受控文件（11）、物料检验放行（12）、上市放行签批和受托厂出厂放行（13）、出厂检验报告编号（14）、留样地点（15）、逐批留样（16）、审计日志和电子签批（17）、销售记录的备案编号、净含量、价格和购买者地址联系方式（19）、过期成品在库（20）、退货（21）、超过 30 天没关的投诉（22）、没上报的不良反应（23）、召回（24）。第 1、3、5、8、18 项要人工检查 | `GmpEvidenceService` |
| 年度提醒 | 签批过的才按 12 个月提醒（到期前 30 天开始，超期算紧急），发给 QA、QSO；从没做过的只在上线检查提示。待签批的提醒发给 QSO | `DashboardService`、`GoLiveService` |
| 报告 | 打印页 A4 纵向：基本信息、结论、检查结果统计、总结和 24 项明细（结果、问题、CAPA 编号）；没签批的顶部标明仅供参考 | `SelfCheckReportPrint.vue` |

## 没有做的

- 变更控制和供应商、工艺、受控文件等操作没有联动（配方和标签设计稿已联动，开关默认关闭）。
- 标签设计稿：核对印刷内容和样张靠人工确认，系统不比对图片和颜色；供应商不能在门户里上传样张；旧版印刷的包材不自动冻结。
- 受控文件：培训考核不做题库和在线答题，成绩由质量人员线下考完后登记；没考核通过不限制操作。
- 新品：项目预算和成本（涉及价格权限，没有做）、阶段计划和甘特图、多个成品规格（同一项目多个 SKU）。
- 质量标准：按批量自动算抽样数量（现在取样要求只是一段文字）、取样扣库存、按项目设不同的自检周期（现在一个标准一个上限）、供方报告和采购单或送货通知逐批对应、检验结果趋势图。
- 稳定性：打印报告上的电子签名图样和公司抬头；方案修改不需要第二人批准（要的话改成和结果更正一样）。
- 自动获取法规更新。
