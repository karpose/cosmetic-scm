# 运维规程（SOP）

## SOP-01 备份与恢复

1. **自动备份**：docker compose 的 `backup` 服务每天 `SCM_BACKUP_AT`（默认 02:30）用 `mysqldump --single-transaction`
   备份到 `./backups/cosmetic_scm-日期-时间.sql.gz`，并把附件卷打包到 `./backups/files-日期-时间.tar.gz`，自动校验压缩包，保留 `SCM_BACKUP_KEEP_DAYS`（默认 30）天。
2. **异地保存**：运维每天把 `./backups` 同步到另一台机器或对象存储（如 `rclone sync` / 云厂商同步工具）。
   本系统不自动做这一步，因为目标位置和凭据由公司 IT 决定。
3. **手工备份**（升级、迁移前必做）：`docker compose exec backup /scripts/backup.sh once`
4. **恢复**：
   ```bash
   docker compose stop backend
   docker compose exec backup /scripts/restore.sh /backups/cosmetic_scm-20261103-0230.sql.gz   # 按提示输入 YES
   # 恢复附件：用同一时间点的压缩包；卷名是“项目名_files-data”
   docker compose run --rm --no-deps -v cosmetic-scm_files-data:/restore --entrypoint tar backup -xzf /backups/files-20261103-0230.tar.gz -C /restore
   docker compose start backend
   ```
   恢复后抽查几个批号的追溯，下载一个附件确认能打开，并在变更记录中登记。
   备份时先导数据库、再打包附件，所以同一时间点的压缩包一定包含数据库里登记的所有附件；
   恢复后卷里可能多出备份之后才上传的文件，它们没有数据库记录，不影响使用。
5. **恢复演练**：每季度在验证环境恢复一次最近的备份，记录耗时和抽查结果。

## SOP-02 变更控制

1. 任何代码、配置、数据库结构的变更先提变更申请：内容、原因、影响的 URS 编号。
2. 质量部按风险评估决定再验证范围：影响“关键”需求的，重跑相关 OQ 用例；仅界面文字、样式的，记录即可。
3. 代码变更必须走 Pull Request，GitHub Actions 的后端测试、前端构建、冒烟测试全部通过才能合并。
4. 数据库结构只能通过新增 Flyway 迁移脚本修改，**不得修改已执行的脚本**。
5. 上线前手工备份（SOP-01 第 3 步）；上线后记录新的 Git 提交号。

## SOP-03 账号与权限

1. 新员工按岗位申请角色，部门负责人审批后由管理员开通；初始密码线下告知，首次登录强制修改。
2. “质量安全负责人”角色只授予质量安全负责人及其书面指定的协助人员。
3. 受托厂、经销商用门户账号，必须绑定所属单位；合作终止当天停用。
4. 离职、转岗当天停用或调整账号。
5. 每季度导出账号与角色清单，由各部门负责人确认，留存记录。
6. 账号被锁定时，管理员核实是本人操作后再解锁；短时间多次锁定按安全事件处理。

## SOP-04 审计日志复核

1. 质量部每月在“审计日志”中复核：上市放行、拒收、冻结 / 解冻、报废、召回、账号变更、主数据导入、扫码核对不一致的记录、配方变更生效、关闭偏差、供应商审核、销毁留样、导出报表。
2. 关注：非工作时间的签批、同一人短时间大量操作、“登录锁定”记录。
3. 发现异常记录原因和处理结果。审计日志在系统中只增不改，不提供修改和删除功能。

## SOP-06 偏差与 CAPA

1. 发现偏差的岗位当班在“质量体系”登记。等级由质量部判定：可能影响产品质量或合规的按重大及以上处理。
2. 重大及以上的偏差要关联批次：未关闭时这批不能放行。过程检验超限由系统自动生成重大偏差。
3. 质量部在期限内调查根本原因，制定 CAPA；负责人完成后，由完成人以外的人验证有效性；验证无效退回继续。
4. CAPA 全部验证有效后，质量人员写明结论和批次处置意见并签批关闭；严重偏差由质量安全负责人关闭。

## SOP-07 配方变更与备案

1. 任何配方修改都在“配方与备案”发起变更，写明内容和原因。首版配方上线初始化时录入，由质量部人工核对与备案资料一致。
2. 系统判断原料是否变化（增、删、用量）。变化的先完成备案变更，登记编号后才能签批；只换包材不需要备案，但仍要签批。
3. 质量安全负责人签批生效。还没发料的生产单自动改用新版本（审计日志列出单号）；已发料的按原版本继续。
4. 特殊化妆品注册证到期前 180 天开始提醒，到期后不能上市放行。

## SOP-08 消息提醒

1. 配置方法见 README 部署一节。提醒只是辅助，到期事项的责任人仍以总览待办为准。
2. 每月在“消息提醒”查看发送记录；连续失败时检查 SMTP 或群机器人配置。群机器人地址等同密码，泄露后立即在企业微信里重置。

## SOP-05 故障处理

1. 监控 `/api/health`（数据库不通时返回 503）；`docker compose ps` 中 backend 应为 healthy。
2. 系统不可用期间按纸质记录作业，恢复后补录，并在审计日志中可以追溯到补录人和时间。
3. 数据疑似损坏时立即停止写入，按 SOP-01 评估是否从备份恢复。
