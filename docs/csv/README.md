# 计算机化系统验证（CSV）文档包

依据《化妆品生产质量管理规范》附 1“计算机化系统”的要求，参考 GAMP 5 的风险为本方法编写。
本系统按 GAMP 5 归类为 **第 5 类（定制开发软件）**，验证范围覆盖所有影响产品质量和数据完整性的功能。

这些文件是**模板 + 已填好的系统内容**：需求、风险、测试用例都已按本系统写好，
上线前由质量部门补齐执行记录（结果、证据、偏差）并签字批准。

| 文件 | 内容 | 由谁执行 / 批准 |
| --- | --- | --- |
| [01-用户需求说明-URS.md](01-用户需求说明-URS.md) | 系统必须满足的业务和合规需求，每条有编号 | 质量部批准 |
| [02-风险评估.md](02-风险评估.md) | 每项需求失效的影响、可能性、可检测性，以及系统里的控制措施 | 质量部 + IT |
| [03-安装确认-IQ.md](03-安装确认-IQ.md) | 服务器、软件版本、配置、备份是否按要求安装 | IT 执行，质量部复核 |
| [04-运行确认-OQ.md](04-运行确认-OQ.md) | 逐条验证功能和控制是否按设计工作；含需求↔测试追溯矩阵 | 质量部执行 |
| [05-性能确认-PQ.md](05-性能确认-PQ.md) | 用真实主数据和真实业务跑一段时间，确认满足日常使用 | 业务部门 + 质量部 |
| [06-运维规程-SOP.md](06-运维规程-SOP.md) | 备份恢复、变更控制、账号与权限复核、审计日志复核、故障处理 | 质量部批准，IT 执行 |
| [07-部署预验证记录-2026-11-03.md](07-部署预验证记录-2026-11-03.md) | 开发机上用生产 compose 文件完整演练一遍部署、备份和恢复的结果 | 参考，不代替正式 IQ |

## 执行顺序

1. URS、风险评估批准后，冻结本次验证的软件版本（Git 提交号写进 IQ）。
2. 在**正式环境**完成 IQ。
3. 在与正式环境相同配置的**验证环境**执行 OQ：自动化部分运行测试并保存输出，手工部分逐步截图。
4. 上线后执行 PQ（建议 1–3 个月）。
5. 出具验证报告，系统正式放行使用。之后的每次变更按 SOP 的变更控制评估是否需要再验证。

## 自动化测试作为验证证据

OQ 里标了“自动”的用例对应代码里的测试方法，执行方式：

```bash
cd backend && mvn clean test                 # 后端单元测试 + 集成测试
cd frontend && npx playwright install chromium && npm run e2e   # 端到端冒烟测试
```

保存命令输出（含提交号、时间、通过数）作为执行记录。GitHub Actions 的每次运行记录也可以作为补充证据。
